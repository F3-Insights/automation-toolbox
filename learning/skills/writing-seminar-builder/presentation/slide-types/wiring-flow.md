## System wiring flow (mental model · inputs→process→outputs)

`purpose:` Demonstrate · `when-to-use (trigger):` you need to show how **one concrete system** is wired (what it reads, what it does step by step, and what it produces) and a bullet list would flatten the structure. Use it when the beat is "here is a real, multi-step artifact (a Skill, a pipeline, an automation), drawn so it feels built, not described." · `density:` V · `element:` wiring-flow · `animation:` stage labels + source nodes from entry; the core (with its numbered steps) and result reveal left-to-right over two presses; an optional framework call-back line + takeaway land on the third · `lineage:` Demonstrate family, sibling to Worked example and Step-by-step build; the thin-stroke architecture idiom of the brand's architecture reference deck (in the `brand-guide` skill), rendered in the deck's data-ink CSS rather than Mermaid · `build-priority:` codes the long-standing "Mental model (inputs→process→outputs)" row in `_INDEX.md` §3.

Reach for it when the story beat is "let me show you the actual wiring of this one thing." Three source nodes (solid = a live service/connection, dashed = your own file/config) feed a gold core that carries the multi-step body, which feeds a single result node; one gold connector per zone reads as the flow without drawing brittle many-to-one lines. It pairs well with a Worked example earlier (the abstract recipe) or a live demo after (the same system running). Keep it to ~3 inputs and ~5 core steps so the columns stay peers and the connectors hit center. Optionally tag the nodes (`.wn-tag` Context/Tool, `.wn-tag--prompt` for the focus) and add an `.eaf-ref` line to map the system back onto the Effective Agentic Framework and hand off the other categories to their sibling seminars, so a worked system late in a deck ties back to the framework slide that opened it.
