# Consulting & Recommendation Decks: Learnings

*How to build a deck whose job is to **drive to a recommendation and make the argument easy to follow**. Read [_universal.md](_universal.md) first; this doc covers what's specific to consulting / advisory decks.*

Use: proposals, strategy reviews, board recommendations, advisory deliverables. Not the teaching-seminar shape: here the audience wants the answer, then the support, fast.

---

## The job

Get to the recommendation and make the logic effortless to verify. Executives want the **story arc, not the data dump**. Minimalist layouts, one claim per slide, generous white space: the so-called "McKinsey style."

---

## Principles

1. **Open with SCQA.** Situation → Complication → Question → Answer. Establish the reality the audience already accepts, surface the tension that disrupts it, frame the implied question, then deliver the answer. This beats chronological ("here's everything we did") storytelling every time.

2. **Answer first (the Pyramid Principle).** Lead with the governing thought / recommendation, then the supporting arguments, then the evidence beneath them. Every idea summarizes everything below it. Top-down, not detective-story.

3. **MECE.** Any breakdown (issue tree, recommendation groups, option list) must be Mutually Exclusive and Collectively Exhaustive: no overlaps, no gaps. It's the validity test for the structure.

4. **Action titles that state the "so what."** Every title is a complete, verb-driven sentence asserting the conclusion ("Direct outreach drives growth; added focus can lift revenue 10–15%"), not a label ("Revenue overview"). ≤15 words, never more than two lines. Write the title first.

5. **Horizontal + vertical logic.** Horizontal: reading only the titles, cover to cover, tells the whole story (this is how you QA the storyline). Vertical: within a slide, the body proves the title and nothing else.

6. **Ghost-deck the storyline first.** Before building anything, draft the slide-by-slide action titles with rough sketches of each exhibit, with no design, no charts. It's the logical skeleton and the work plan, and it aligns stakeholders on the argument before production time is spent.

7. **One claim + its evidence per slide.** Point at any element and ask "so what?"; if it doesn't serve the title, cut it.

8. **Standard charts over fancy visualizations.** Pick the chart from the message (see [financial-data-decks.md](financial-data-decks.md) for the message→chart map). Bar charts and simple comparisons enable fast comprehension. Clarity beats cleverness; maximize data-ink, cut chartjunk.

9. **Restraint and consistency.** 3–4 colors, accent only on the point that matters; fixed title position and size on every slide; a source line on every data claim; graspable in ~60 seconds.

---

## Storyline shape

SCQA opening → (framework that organizes the analysis) → analysis slides, each one claim → **recommendation summary** → **next-steps / action plan** (owner, date) → appendix for defense material kept out of the main flow.

---

## Consulting slide types (Orient / Compare & decide / Prove / Recommend & close)

executive summary (SCR) · situation / fact-base · framework figure · issue/driver tree (MECE) · 2×2 matrix · comparison table (Harvey balls) · waterfall (bridge) · ranking bar · trend · composition · scatter/bubble · value chain · process flow · roadmap/Gantt · dashboard/KPI · recommendation summary · next-steps · appendix.
