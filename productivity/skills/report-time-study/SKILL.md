# Executive time study

The procedure `time-study-orchestrator` follows, for one owner and one period: every day of the period, ten-minute slot by slot, with the evidence for each. Run it as that agent, the main session, because it fans out many workers; a sub-agent cannot. It reads nothing in bulk itself; workers read transcripts and signal files, and code does every sum.

It runs unattended. Nothing is asked live: the questions only the owner can settle go into each window's `questions.md`, its report and the Run's report as one numbered list with proposed answers, and the owner answers when they choose, through the next launch's Answers or a file in the window. Nothing the owner has not said is written into their rules.

**The home (H)** is the time-study tool's private home folder, given as the Time-study home input. It holds the owner's `domains.csv`, `groups.csv`, `topics.csv` and `mapping.md` (the standing rules, and the map from people, repositories and folders, email domains, Teams tenants, websites and recurring meetings to domains), one folder per window under `H/data/raw/<D1>_to_<D2>/` (W below), the built tables in `H/data/`, and the dashboard, reports and said-but-not-seen files in `H/out/`. Nothing the owner owns is kept in this repository.

**The tool** is a separate time-study program (`python -m timestudy`): it collects, validates, builds the tables and draws the dashboard. Its home is normally `private/` inside its own folder, and `python3 ~/.claude/skills/report-time-study/scripts/time_study_tool.py H <command>` runs it from there (or from the checkout `--repo` or the `repo` setting under `[report-time-study]` names; H itself can come from the `home` setting there), so every call is one plain command. The commands around it:

```bash
python3 ~/.claude/skills/report-time-study/scripts/time_study_check.py H [--period P] [--window W] --format json   # done, test by test; --precheck for the scheduler
python3 ~/.claude/skills/report-time-study/scripts/time_study_collect.py H [--period P] [--window W]                # collect every window not yet collected
python3 ~/.claude/skills/report-time-study/scripts/time_study_tool.py H build | summary | dashboard                 # the tool itself; --save FILE keeps the output
python3 ~/.claude/skills/report-time-study/scripts/time_study_day_lint.py H/data/raw/W/days/D --domains H/domains.csv [--topics H/topics.csv]
python3 ~/.claude/skills/report-time-study/scripts/time_study_said_not_seen.py H/data/raw/W [--review W/said-not-seen-review.json]
```

`rules.md` beside this file holds the mechanics: the window layout, the worker models and fan-out limits, the verification checks, the questions, the report, the said-but-not-seen file and the privacy rules. The worker briefs are `briefs/meeting-segmenter.md`, `briefs/day-assembler.md`, `briefs/topic-classifier.md` and `briefs/checker.md`, each with a fixed return format, each run by its registered agent (`time-study-meeting-segmenter`, `time-study-day-assembler`, `time-study-topic-classifier`, `time-study-checker`), which pins the model and tools. Why the study has this shape is `DESIGN.md`.

**User provided:** $ARGUMENTS

## Steps

1. [script] Scope the Run. Under a scheduled Automation, `time-study-collect` has already collected every window the Run needs (its first line is in the inputs); started by hand, run `python3 ~/.claude/skills/report-time-study/scripts/time_study_collect.py H --period P --window W` first. Then run `python3 ~/.claude/skills/report-time-study/scripts/time_study_check.py H --period P --window W --format json`. Its `windows` and `new_windows` are the Run's windows, in date order, each with the tests still open. On a dry run, stop here and report the plan: each window, what it lacks, the dispatches it needs, and the collect line. → every test met and no answers given: stop → the check could not run: stop
2. [judgment] Frame each window, oldest first. Read W's `run-log.md` (what earlier runs did and left open), `coverage.md` (each source per day: a count, or null and why), H's `mapping.md`, `domains.csv` and `topics.csv`, and W's `owner_stated.md` and `calls_confirmed.csv`. A window the collect could not fill is recorded as a gap in its run log and the Run's report, and the Run goes on with the others. When the Answers input is given, save it verbatim as `W/answers-<today>.md` in the window it names (or the one window with open questions) before anything else. → no domains.csv in H: stop
3. [hand-off: time-study-meeting-segmenter] Dispatch one `time-study-meeting-segmenter` per recording in `W/recordings.json` that has no `meetings/<recording_id>.md`, in parallel within the fan-out limit in `rules.md`, whose prompt is the path of its own `W/work/segmenter-<recording_id>/input.json` and nothing else; the agent reads `briefs/meeting-segmenter.md` itself. A MISMATCH or BLOCKED recording is a gap for the report, not a stop. → returns read: step 4
4. [judgment] Verify every new segment file against `recordings.json` with the checks in `rules.md` ("Checking a segment file"). Re-dispatch a failing recording once with the failure named; one that fails again is a gap in the report. → a file fails: step 3 (max 1)
5. [hand-off: time-study-day-assembler] Dispatch one `time-study-day-assembler` per day that lacks `slots.csv` or `day.md`, in parallel within the limit, whose prompt is that day's input paths (the agent reads `briefs/day-assembler.md` itself): `W/signals/<date>/`, the segment files dated that day, W's `owner_stated.md` and `calls_confirmed.csv`, and H's `mapping.md` and `domains.csv`. Each writes `W/days/<date>/slots.csv` and `day.md`. This step re-runs once for the days that step 10's answers or step 8's accepted flags change, in one pass carrying both, with the day's previous files to revise; neither loop re-runs a day on its own. → BLOCKED: step 6
6. [hand-off: time-study-topic-classifier] Dispatch one `time-study-topic-classifier` per day that lacks `topics.csv` or whose slots changed, in parallel within the limit, with that day's paths and H's `topics.csv`, `mapping.md` and `domains.csv`; the agent reads `briefs/topic-classifier.md` itself. → BLOCKED: step 7
7. [script] Run `python3 ~/.claude/skills/report-time-study/scripts/time_study_tool.py H build`. It stops on a day without 144 contiguous slots, a slot whose shares do not sum to 1, an unknown domain, or a topics file that misses a slot or names an unknown topic, and names the file and the row. → a slots.csv fails: step 5 (max 1) → a topics.csv fails: step 6 (max 1)
8. [hand-off: time-study-checker] Dispatch one `time-study-checker` per window that has no `check.json` or whose slots changed, whose prompt is the paths of each day's `slots.csv` and the raw evidence (W's `signals/`, `meetings/`, `owner_stated.md`, `calls_confirmed.csv`, H's `mapping.md` and `domains.csv`), never `day.md` or an assembler's return: the check is worth something only if the checker has not seen the reasoning. The agent reads `briefs/checker.md` itself. Save its JSON block as `W/check.json` and read every flag against the evidence it cites. A flag that holds up is applied in step 5's single re-run, with the owner's answers when there are any; a flag the evidence cannot settle becomes a question. → flags read: step 9
9. [judgment] Write the questions. Build the full set from every `day.md`, the checker's flags and the segmenters' returns, in the order `rules.md` ("The questions") gives, each with its evidence and a proposed answer, and save it as `W/questions.md`, ending with the short list: the handful only the owner can settle, then one final item, "accept every other proposed answer and every checker flag". Nobody is asked now; the list goes in the report and the Run's report. → answers saved for this window: step 10 → no answers: step 11
10. [judgment] Apply the owner's answers. The final item's "ok" is the owner's answer to every proposed answer and flag the list did not ask about. A standing rule (true every time: for example a person's calls split 70/30 between two projects, evening gaps are personal) becomes a row in H's `mapping.md`, in the table of its kind, marked confirmed by the owner with the answers' date. A one-off fact goes to W's `owner_stated.md`, and a call span the owner confirms to `calls_confirmed.csv` with the evidence in `note`. An owner-stated time that conflicts with a verified one is recorded as stated and the conflict stays in the report; it never overwrites the verified time. Note in `run-log.md` which days change. → answers or accepted flags change a day: step 5 (max 1) → no day changes: step 11
11. [script] Run `python3 ~/.claude/skills/report-time-study/scripts/time_study_tool.py H build`, then `python3 ~/.claude/skills/report-time-study/scripts/time_study_tool.py --save H/out/summary-<window>.txt H summary` and `python3 ~/.claude/skills/report-time-study/scripts/time_study_tool.py H dashboard`. → build fails: stop
12. [judgment] Settle said but not seen across the window. For each item in the days' said-but-not-seen sections, look in the later days' `## Done` sections and signal files for the commitment being kept. Write `W/said-not-seen-review.json` (an item's `id` or `ref` to `status` seen or dropped, with the `evidence` or `note`; open items are left out), then run `python3 ~/.claude/skills/report-time-study/scripts/time_study_said_not_seen.py W --review W/said-not-seen-review.json`. It writes `H/out/said-not-seen-<window>.json`, the file other orchestrators read. → written: step 13
13. [judgment] Write the report, `H/out/report-<window>.md`, in the order `rules.md` ("The report") gives. Every hour and count is copied from the summary or the built tables, never added up by the model. When questions are still open, the report's second line is "provisional: questions open" and the short list closes it. Append to W's `run-log.md` what ran, what each source gave, the answers applied and what is still open. → another window: step 2 → every window reported: step 14
14. [script] Run `python3 ~/.claude/skills/report-time-study/scripts/time_study_check.py H --period P --window W` last and report its result: per window the report's path and the three findings that most change the owner's picture, the said-but-not-seen counts and file, and every window's short question list, numbered, as the Run's questions for the owner. Done when the check meets every test; a window waiting on answers is done for this Run. → reported: done

On a stop, say why in one line and what the owner can do about it: the source that failed with its reason, the window that already holds a date, or the build's own message.

## When the session runs short

A month is many dispatches. Finish the window in hand to a report (provisional, naming what is missing) before starting another, and never leave a window with day files newer than its report. The next Run starts from `time-study-check`, which shows what is left.

## Where the output goes

All of it under H, which the tool's repository ignores as a whole: the window's signals, segment files, day files, questions, answers, check, review and run log in W; the owner's standing rules in `H/mapping.md`; the built tables in `H/data/`; the dashboard at `H/out/dashboard.html`; the summary, the report and the said-but-not-seen JSON in `H/out/`. Never a hosted page, never a commit, never a message, unless the owner asks for something shareable.
