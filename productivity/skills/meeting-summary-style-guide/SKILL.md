# Meeting Summary Style Guide

This skill defines how meeting summaries generated by `meeting-summary` look and read. An owner who wants a different house style edits it.

---

## Voice & Tone

- Professional but conversational, not corporate stiff
- Active voice, specific details (tools named, numbers cited, dates included)
- Executive summary style: distill and synthesize, never transcribe
- Confident and direct, no hedging ("It seems like participants might have...")
- Dense and information-rich: every sentence should carry weight

---

## Anonymization Rules

Anonymization is chosen **per summary** during the context confirmation step. Three modes:

### Mode A: Full Anonymize
- **No names at all**: every participant becomes "one participant," "a member noted," "the group agreed," "several attendees"
- No initials, job titles, or identifying role descriptions
- Paraphrase rather than using direct quotes with attribution

### Mode B: Anonymize Except Me (Default)
- The **user's name** is used (asked during context confirmation, not hardcoded)
- All other participants are anonymized using varied attribution: "one participant," "a member noted," "the group agreed"
- No initials, job titles, or identifying descriptions for anyone except the named user
- The named user can be referenced when they lead, present, or demonstrate

### Mode C: No Anonymization
- **Names and/or initials used freely** throughout the summary
- Still paraphrase for flow; don't force direct quotes just because names are available
- Use first name or full name consistently (ask user preference if unclear)

## Document Structure

### Title & Metadata
```
# [Group/Meeting Name] - [Purpose/Topic] Summary
**Date:** [Month Day, Year] at [Time] [TZ] via [Platform] | **Duration:** ~[X] hour(s)
```

- NO horizontal rules (`---`) between sections; sections flow directly
- Title gets a blue underline (handled by PDF CSS)

### Content Style: Paragraphs, Not Bullets

**This is critical.** The summary uses a **paragraph-driven** format with bold lead phrases, NOT bullet-point lists.

Each section contains flowing paragraphs where the first phrase is bolded to serve as a scannable label:

```
**Close Calendar Pressure:** The team closes in eight working days and wants six.
Most of the slack sits in the last two days, waiting on reconciliations that
could start earlier.

**The Spreadsheet Sprawl Problem:** A key discussion emerged around duplicate
workbooks. Each region keeps its own copy of the accrual schedule, so the same
fix is made three times. Consensus: one shared schedule, owned by the controller.
```

When to use bullets instead of paragraphs:
- The **Chronological Topics** section (see below): compact one-line bullets with timestamps
- Very short lists (resources, links) at the end of the document
- Never for other main content sections

### Long Workshops (60+ minutes)

For extended sessions like multi-hour workshops or learning sessions, add a **Chronological Topics** section. This gives readers a scannable timeline of everything covered, like a table of contents for the meeting.

**Format:** Compact bullet list. Each item is one line: **timestamp + bold topic + brief description** (~30 words max per line).

```
## Chronological Topics

- **0:08** Close Calendar Review: day-by-day walk through last month's close, where the waits were
- **0:20** Reconciliation Tool Demo: live walkthrough of matching rules, exception queue and sign-off
- **0:39** Accrual Schedule Rebuild: one shared schedule drafted together in about 20 minutes
- **0:49** Controls Discussion: who reviews what, evidence kept, and what the auditors will ask for
```

**Recommended structure for long workshops (5 sections):**
1. Executive Summary (2-4 sentences)
2. Chronological Topics (compact timeline, the only section that uses bullets)
3. Key Concepts (synthesized technical takeaways, paragraph style)
4. Discussion Highlights (major conversation threads, paragraph style)
5. Decisions & Next Steps (action items, logistics, resources)

The Chronological Topics section replaces the need for Workshop / Live Demo Highlights; it covers the full session flow. The other sections then synthesize across topics rather than repeating chronologically.

**Page target for long workshops:** 2-3 pages (the chronological list adds ~half a page).

### Section Selection
Choose **4-6 sections** from the catalog below based on content. Keep it tight.

---

## Section Catalog

| Section | When to Use |
|---------|-------------|
| **Executive Summary** | Almost always. 2-4 sentences. |
| **Chronological Topics** | Long workshops (60+ min). Compact timestamped bullet list. |
| **Key Takeaways / Key Concepts** | Core insights. Bold lead phrases + paragraph text. |
| **Tools Discussed** | Each tool: **Tool Name:** description as flowing text. |
| **Discussion Highlights** | Major conversation threads. Bold lead + paragraph. |
| **Workshop / Live Demo Highlights** | Short meetings with a demo. Not needed if using Chronological Topics. |
| **Decisions & Next Steps** | Concrete decisions. **Bold label:** details as text. |
| **Key Philosophical Points** | Principles and values discussed. Bold lead + text. |
| **Resources** | Links shared. Bullet list under Decisions & Next Steps. |
| **Appendix: [Topic]** | Supplementary data (e.g., poll results). Starts on new page. |

## Formatting Rules

### Bold Lead Phrases (Paragraph Style)
Every content paragraph starts with a **bolded key phrase** followed by a colon, then the content flows as a normal paragraph:

```
**Framework for a Faster Close:** A four-part framework was presented: Calendar
(what happens on which day), Owners (one name per task), Evidence (what proves a
task done) and Review (who signs off). Key insight: most teams fix the calendar
and skip the evidence.
```

Do NOT use bullet points for these; they are paragraphs.

### Tool Descriptions
List tools as individual paragraphs with bold names and colons:

```
**Reconciliation tool:** Matches bank lines to the ledger by rule and queues the
exceptions. One participant noted it "cut the bank rec to an hour."

**Shared workbook:** The presenter's primary tool for the accrual schedule. One copy,
one owner, with a change log on its own tab.
```

### Decision Items
Decisions use bold labels with inline text (not tables unless there are 4+ items):

```
**Frequency:** Every two weeks, Tuesday mornings preferred.
**Format:** Focused sessions with one worked example; discussion afterwards.
**Action Items:** The organizer to send the summary and propose the next date. All to bring
one close task worth automating.
```

Action items may include status annotations when the summary is distributed after completion: `(NOW DONE!)`, `(In progress)`, etc.

### Resources List
Resources go at the end of Decisions & Next Steps as a **bold label + bullet list**. Include current, actionable links: not just what was mentioned during the meeting, but updated links if things have changed (e.g., a shared channel was created after the meeting).

```
**Resources:**

- Team channel: https://example.com/channel
- Official docs: https://example.com/docs
- Recordings: available in the team channel
```

**Markdown formatting note:** There MUST be a blank line between `**Resources:**` and the first bullet. Without it, markdown renders everything as a single paragraph.

### Tables
- Use only for genuinely tabular data (poll results, structured comparisons)
- Blue header rows with white text (handled by PDF CSS)
- Keep tables compact: short descriptions, abbreviate where possible
- Tables should be in the Appendix when they're supplementary data

### No Horizontal Rules
Do NOT use `---` between sections. Sections are separated by their headers alone. The only exception is one rule after the metadata line if desired.

---

## Page & Length Targets

- **Standard meetings: 1-2 pages** in PDF (letter size, 0.5" margins, 9.5pt body)
- **Long workshops (60+ min): 2-3 pages**; the chronological topics list adds ~half a page
- **Appendix:** If included, starts on its own page
- The paragraph style is inherently more compact than bullet lists
- If content runs long, merge related points into fewer paragraphs
- Aim for density: if a sentence doesn't add information, cut it

---

## Quality Checklist

1. Anonymization mode applied correctly (full / except-me / none)
2. Bold lead phrases start every content paragraph
3. Paragraph style throughout; bullets only in Chronological Topics and resource lists
4. Standard meetings fit 1-2 pages; long workshops fit 2-3 pages
5. Executive Summary is 2-4 sentences
6. Chronological Topics (if used) are one line each, ~30 words max
7. All sections have substance, no filler
8. Specific details: tool names, percentages, dates, decisions
9. Resources are a bullet list with current, actionable URLs
10. Appendix (if any) on its own page with compact tables

## Color Scheme (handled by PDF CSS)

- **H1 (title):** Dark text with blue underline
- **H2 (sections):** Steel blue (#3b6fa0)
- **H3 (subsections):** Darker blue (#2c5282)
- **Table headers:** Blue background (#3b6fa0) with white text
- **Alternating rows:** Light blue-gray (#f0f4f8)
