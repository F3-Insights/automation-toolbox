# Slide type: Comparison table (Harvey balls / RAG)

`purpose: Compare & decide · when-to-use (trigger): several options scored against the same criteria, and one is the recommendation · density: B · element(s): comparison-table (scored grid + Harvey balls or RAG cells) · animation: grid + criteria (1) to scores cascade row by row (2) to recommended column highlight (3) · lineage: new in the Compare & decide family; borrows the .analogy header treatment, the navy/gold encoding of .tri, and the row-spine discipline of .before-after · build-priority: consulting/data set (was the comparison-table ◻ row in _INDEX §4)`

Reach for the **comparison table** when the beat's job is to make a multi-option choice defensible on one page: three to four options across the top, the criteria that matter down the side, and a score in every cell so the audience can read the trade-off at a glance and arrive at the same answer you did. Use Harvey balls (empty to full) when the criteria are judgment ratings on a shared scale, or RAG cells (red, amber, green) when each criterion has a clean threshold. One option is the recommendation: its column carries the single gold accent and a "Recommended" tag, while the rest stay quiet navy, so the slide argues for a conclusion rather than just tabulating. It is the Compare & decide type for when the choice has more than two contenders and more than one dimension. If there are only two states of the same thing, use before / after. If the options live on two decision variables, use a 2x2 matrix instead. Keep it to roughly four options by six criteria so every cell stays legible. Always print a legend, and cite the scale or source when the scores lean on a named benchmark like APQC.
