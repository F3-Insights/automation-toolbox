# 0004. A department is a standalone plugin, with light agents, skills and named commands

Status: accepted, 2026-10-11, for the software department first; the other departments follow one at a time. Amends [0002](0002-commands-live-inside-skills.md) decision 5 and [0003](0003-agent-files-follow-one-template.md) for a department that is a plugin.

## Context

Every agent and skill was linked into one flat folder (`~/.claude/skills`), so every session listed all of them, and commands ran by a path into that folder. Agents carried their procedures, and each specialist step was its own agent. A probe on Claude Code 2.1.296 showed that a plugin's `bin/` is on PATH and can be named in a permission rule (`Bash(demo-hello:*)`), that a path through `${CLAUDE_PLUGIN_ROOT}` cannot be, and that a main session started with `--agent` does not preload its `skills:`.

## Decision

1. **A department is one Claude Code plugin:** `<department>/.claude-plugin/plugin.json` (name = the department), with the department's `agents/`, `skills/` and `bin/`. It depends on no other department; what it needs from another is copied into one of its own skills.
2. **One lightweight main agent per job** (what one Automation launches): an opening sentence, `## Goal`, `## Inputs`, `## Done`, `## Never`, `skills:` and `tools:`, about 50 lines. Its first instruction is to load its skills with the Skill tool. The procedure, checklists, formats and the former specialists' instructions are `##` sections of the job's skill.
3. **Dispatch only for independence or for parallel or isolated work,** to two department agents: `<department>-reviewer` (judges from the sources alone against the checklist section it is told to use; PASS or FAIL with numbered fixes; edits nothing) and `<department>-worker` (does one slice, following the section it is told to use, and returns that section's block). Where the main agent can do a step itself, it does.
4. **Scripts are named commands:** each script in a skill's `scripts/` (not helpers, templates or tests) gets a wrapper `<department>/bin/<department>-<name>` generated by `scripts/build_bins.py <department>`. Skills use the name; agents grant `Bash(<command>:*)`. `scripts/toolbox_check.py` fails on a missing or stale wrapper, a wrapper with no script, or a `~/.claude/skills/` path in a plugin department's Markdown.

## Consequences

- The scripts stay where 0002 put them; only the way callers name them changes.
- Agent and skill names stay unique across the toolbox, so the flat link folder keeps working for departments not yet migrated.
- Under a plugin, names gain a prefix (`software:software-developer`); a runtime may launch either form.
- `orchestrator-scaffold` writes command rules and skill-loading lines in the plugin form when the target department is a plugin.
