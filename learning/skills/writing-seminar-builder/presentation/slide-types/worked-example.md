# Slide type: Worked example

**Purpose:** Demonstrate · **When to use (trigger):** the audience needs to see a single instance solved end to end, with the reasoning made visible, not just the answer asserted. Reach for it right after you introduce a method or a rule of thumb, when an executive's likely reaction is "show me how that actually plays out on a real number." · **Density:** B · **Element:** worked-steps (`.worked`) · **Animation:** problem statement visible from entry; each reasoning step reveals on its own press (a true sequence, one beat per step); the result highlights last. · **Lineage:** reuses the `data-build` step pattern (DESIGN-PRINCIPLES §6) and the navy `.def-block` definitional frame; the numbered-step treatment is new (`.worked`). · **Build-priority:** first wave (highest teaching value, no element yet).

Worked examples are the single strongest evidence base for teaching novices (the worked-example effect): a smart non-expert who watches a problem get solved, step by reasoned step, internalizes the method far better than one handed only the answer. Use this type when you have just taught a framework or rule and want to ground it in one concrete, believable instance from the audience's world. Present the correct example first, keep each step to an action plus a brief rationale so the executive sees the *why* behind each move, and let the result land last so the build pays off the setup. Hold the deeper judgment (edge cases, when the rule breaks) for spoken commentary; the slide is the map of the reasoning, not the territory.
